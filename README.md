# Биржа талантов — MVP

Рабочая первая версия биржи, где задачи городских проектов, стартапов и сообществ встречаются с исполнителями. MVP доказывает один полный цикл:

`Task → Application → Assignment → Work → Result → Review`

Продуктовая спецификация и границы MVP описаны в [`docs/product/talent-marketplace-mvp.md`](docs/product/talent-marketplace-mvp.md).

## Быстрый старт

Требуется Node.js 24 или новее. Сторонние npm-пакеты не нужны.

```bash
npm start
```

Откройте `http://localhost:3000`.

Для разработки с автоматическим перезапуском:

```bash
npm run dev
```

База SQLite создаётся автоматически в `data/talent-city.db`, схема и демо-данные инициализируются при первом запуске.

## Основные маршруты

| Маршрут | Назначение |
| --- | --- |
| `/` | главная с двумя ключевыми CTA |
| `/tasks` | каталог, поиск и комбинируемые фильтры |
| `/tasks/:id` | карточка задачи, отклик, кандидаты и matching |
| `/tasks/create` | создание черновика или публикация задачи |
| `/profile/me` | заполнение собственного профиля исполнителя |
| `/profile/:id` | публичный профиль и отзывы |
| `/applications` | все отклики на задачи заказчика |
| `/my-tasks` | созданные задачи, отклики и назначения пользователя |
| `/tasks/:id/work` | статусная работа, результат, приём и отзывы |
| `/admin` | минимальная модерация и продуктовая воронка |

## Реализовано

- Регистрация и вход с `scrypt`-хешированием пароля и `HttpOnly`, `SameSite=Lax` сессией.
- Профиль исполнителя с навыками, опытом, портфолио, форматом, доступностью и ставкой.
- Task со всеми полями из ТЗ, черновиком, публикацией и статусами.
- Каталог с поиском и фильтрами по категории, навыкам, бюджету, сроку и формату.
- Один отклик исполнителя на задачу с ценой, сроком и сообщением.
- Сравнение кандидатов и атомарное назначение одного исполнителя.
- Статусная машина `ASSIGNED → IN_PROGRESS → SUBMITTED → ACCEPTED → CLOSED` и возврат результата на доработку.
- Двусторонние отзывы после принятия результата.
- Rule-based matching: доля требуемых навыков, присутствующих в профиле, плюс список совпадений.
- История статусов, простая модерация и события продуктовой аналитики.
- Адаптивный интерфейс без внешних CDN и клиентских зависимостей.

## Архитектура

MVP намеренно является небольшим монолитом:

```text
Browser SPA (vanilla JS)
        ↓ JSON API
Node.js HTTP server
        ↓
SQLite (node:sqlite)
```

- `src/server.js` — HTTP-сервер, API, права доступа и статусные переходы.
- `src/db.js` — схема SQLite, seed-данные, история и аналитические события.
- `src/auth.js` — пароль и cookie-сессии.
- `src/matching.js` — детерминированный matching и нормализация навыков.
- `public/` — SPA-интерфейс и адаптивные стили.
- `test/e2e.test.js` — полный пользовательский цикл на отдельной временной БД.

SQLite выбран для быстрого пилота и транзакционной целостности. Перед горизонтальным production-развёртыванием следует перенести данные в PostgreSQL, добавить миграции и вынести секреты/конфигурацию в управляемое окружение.

## Проверка

```bash
npm run check
npm test
```

`npm test` поднимает сервер на случайном порту и без ручного изменения БД проходит сценарий:

1. регистрация заказчика;
2. создание черновика и публикация задачи;
3. регистрация и заполнение профиля исполнителя;
4. поиск задачи и проверка matching;
5. отклик;
6. просмотр отклика заказчиком и назначение;
7. старт работы и передача результата;
8. принятие, закрытие и два отзыва;
9. проверка истории и обязательных analytics events.

## Аналитика пилота

Записываются события `user_registered`, `profile_completed`, `task_created`, `task_published`, `task_viewed`, `application_created`, `application_viewed`, `executor_selected`, `task_started`, `result_submitted`, `result_accepted`, `task_closed`, `review_created`.

Admin-панель показывает базовую воронку «задачи → просмотры → отклики → назначения → завершения». Для пилота события хранятся в той же SQLite-базе; это осознанное упрощение.

## Сброс демо-базы

Остановите сервер, удалите файлы `data/talent-city.db*` и запустите приложение снова. Схема и seed-данные будут созданы автоматически. Не удаляйте базу работающего сервера.
